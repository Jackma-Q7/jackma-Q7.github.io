# LiteTrack 网络结构

本文是 LiteTrack-B6 的网络结构笔记，按数据流逐模块拆解：输入裁剪与归一化、Patch Embed、位置编码、目标框 token、Block 内部的注意力与 LayerScale、模板与搜索编码、预测头与解码，每一步都给出张量维度。论文层面的方法与实验见《LiteTrack 论文笔记》。

## 0. 约定
| 符号 | 含义 | B6 取值 |
| --- | --- | --- |
| `B` | batch size | 推理时 1；B6 训练配置 32 |
| `N_t` | 模板 token 数 | 64 = 8 × 8 |
| `N_s` | 搜索 token 数 | 256 = 16 × 16 |
| `D` | 隐藏维度 | 768 |
| `h`、`d` | 注意力头数、每头维度 | 12、64 |
| `D_ff` | MLP 中间维度 | 3072 = 4 × 768 |


## 1. B6 是什么
README 里的型号叫 LiteTrack-B6-3。`B` 是 ViT-Base 的宽度（`D=768`，12 个头），`6` 是骨干层数 `DEPTH`，`3` 是搜索分支读取模板的层数 `AI_LAYERS`。B4、B6、B8、B9 用的是同一份代码，只有后两个数不同。

| 变体 | `DEPTH` | `AI_LAYERS` | 搜索自注意力层数（`DEPTH − AI_LAYERS`） |
| --- | ---: | ---: | ---: |
| B4 | 4 | 2 | 2 |
| B6 | 6 | 3 | 3 |
| B8 | 8 | 3 | 5 |
| B9 | 9 | 3 | 6 |


B6 配置里决定网络结构的项。B6 yaml 覆盖 config.py 的默认值：

| 配置项 | B6 的值 | 作用 |
| --- | --- | --- |
| `MODEL.BACKBONE.TYPE` | `vit_base_patch16_224_CAE` | 骨干用 `CAE_Base_patch16_224_Async`（默认值） |
| `MODEL.BACKBONE.DEPTH` | 6 | 骨干 Block 数，默认 9 |
| `MODEL.BACKBONE.AI_LAYERS` | 3 | 搜索分支读取模板的层数（最后 3 层） |
| `MODEL.BACKBONE.STRIDE` | 16 | patch 边长，也是下采样步长（默认值） |
| `MODEL.HEAD.TYPE`、`NUM_CHANNELS` | `CENTER`、256 | 预测头类型和第一层卷积通道数（默认值） |
| `MODEL.USE_CLS_TOKEN` | `True` | 模板编码时是否加目标框 token |
| `DATA.TEMPLATE.SIZE`、`FACTOR` | 128、2.0 | 模板图边长；裁剪正方形的边长是目标 √(w·h) 的 2 倍 |
| `DATA.SEARCH.SIZE`、`FACTOR` | 256、4.0 | 搜索图边长；裁剪正方形的边长是目标 √(w·h) 的 4 倍 |
| `MODEL.PRETRAIN_FILE` | `cae_base.pth` | CAE 预训练的 ViT-Base 权重（默认值） |


由此得到两个特征图边长（litetrack.py#L156-L158）：模板 `128 / 16 = 8`，搜索 `256 / 16 = 16`。

## 2. 总览
![LiteTrack-B6 网络结构总览](/images/2026/parper/2.Litetrack/litetrack-arch.png)

```plain
【初始化：每段序列一次】
模板图 [1,3,128,128] ─Patch Embed→ [1,64,768] ─+pos_embed_z→ [1,64,768]
初始框 [1,4] ─target_token_embed→ [1,1,768] ─────cat─────────→ [1,65,768]
                                                        │
                                             Block 0 … Block 5（自注意力）
                                                        ↓
                                    去掉第 0 个 token → z_feat [1,64,768]（缓存）

【逐帧】
搜索图 [1,3,256,256] ─Patch Embed→ [1,256,768] ─+pos_embed_x→ [1,256,768]
                                                        │
                                           Block 0 … Block 2（搜索自注意力）
                                                        ↓ [1,256,768]
z_feat [1,64,768] ─────────────cat────────────────────→ [1,320,768]
                                                        │
                                 Block 3 … Block 5（搜索读模板，模板 token 原样透传）
                                                        ↓ [1,320,768]
                                 取后 256 个 token，重排 → [1,768,16,16]
                                                        │
                      ┌──────────────── CenterPredictor ────────────────┐
              score_map           size_map            offset_map
             [1,1,16,16]         [1,2,16,16]         [1,2,16,16]
                      └────── Hann 窗 × score_map → 选峰 → cal_bbox ─────┘
                                                        ↓
                                  cxcywh [1,4] → map_box_back → clip_box → state [4]
```

模板和搜索共用同一个 Patch Embed 和同一组 6 个 Block。模板走完全部 6 层，每段序列只算一次。搜索也走 6 层，每帧都算，其中只有后 3 层能读到模板。

**第一帧：**

**1.** 模板图 [1,3,128,128]：

Patch Embed→ [1,64,768] ─+pos_embed_z→ [1,64,768]

**2.** 初始框 [1,4]：

target_token_embed→ [1,1,768]

**3.** 模板图的 [1,64,768]和初始框[1,1,768]cat[1,65,768]→ Block 0 … Block 5（自注意力）→去掉第 0 个 token → z_feat [1,64,768]（缓存）

**逐帧：**

**1.** 搜索图 [1,3,256,256]

Patch Embed→ [1,256,768] ─+pos_embed_x→ [1,256,768]→Block 0 … Block 2（搜索自注意力）[1,256,768]

**2.** z_feat [1,64,768]（缓存）

Block 0 … Block 2[1,256,768] cat z_feat [1,64,768]为 [1,320,768]→Block 3 … Block 5（搜索读模板，模板 token 原样透传）[1,320,768]→取后 256 个 token，重排 → [1,768,16,16]→CenterPredictor

## 3. 逐模块拆解
### 3.1 输入：裁剪、缩放、归一化
模型从不直接看原图，只看两张以目标为中心裁出的正方形图。`sample_target` 的核心逻辑如下：

```python
    crop_sz = math.ceil(math.sqrt(w * h) * search_area_factor)
    x1 = round(x + 0.5 * w - crop_sz * 0.5)
    x2 = x1 + crop_sz
    y1 = round(y + 0.5 * h - crop_sz * 0.5)
    y2 = y1 + crop_sz
    # … 超出图像的部分用 0 填充（cv.BORDER_CONSTANT）
    resize_factor = output_sz / crop_sz
    im_crop_padded = cv.resize(im_crop_padded, (output_sz, output_sz))
```

裁剪边长和目标的面积开方成正比，所以目标在裁剪图里的大小基本固定。以一个 80 × 60 的目标为例：

|  | 模板 | 搜索 |
| --- | --- | --- |
| `search_area_factor` | 2.0 | 4.0 |
| `crop_sz` | `ceil(√(80·60) × 2)` = 139 | `ceil(√(80·60) × 4)` = 278 |
| 缩放到 | 128 × 128 | 256 × 256 |
| `resize_factor` | 128 / 139 ≈ 0.9209 | 256 / 278 ≈ 0.9209 |
| 目标占裁剪图的宽、高 | 57.6%、43.2% | 28.8%、21.6% |


`Preprocessor.process`（data_utils.py#L11-L17）把裁剪图变成归一化的张量：

```python
        img_tensor = torch.tensor(img_arr).cuda().float().permute((2,0,1)).unsqueeze(dim=0)
        img_tensor_norm = ((img_tensor / 255.0) - self.mean) / self.std  # (1,3,H,W)
```

均值是 `[0.485, 0.456, 0.406]`，标准差是 `[0.229, 0.224, 0.225]`。输出模板 `z [B, 3, 128, 128]`，搜索 `x [B, 3, 256, 256]`。

初始化时还要把初始框换算到模板裁剪图的归一化坐标，得到 `template_bb [B, 4]`。tracker 的做法是 `transform_bbox_to_crop(...).squeeze(1)` 之后转成 `xyxy`（tracker#L62-L64），用到的 `transform_image_to_crop` 是上游函数：

```python
    box_extract_center = box_extract[0:2] + 0.5 * box_extract[2:4]
    box_in_center = box_in[0:2] + 0.5 * box_in[2:4]
    box_out_center = (crop_sz - 1) / 2 + (box_in_center - box_extract_center) * resize_factor
    box_out_wh = box_in[2:4] * resize_factor
    box_out = torch.cat((box_out_center - 0.5 * box_out_wh, box_out_wh))
```

对上面的 80 × 60 目标，实测得到 `template_bb = (0.208324, 0.280266, 0.783864, 0.711921)`。宽等于 80 / 139 ≈ 0.5755，高等于 60 / 139 ≈ 0.4317。

#### 3.1.1 实例
假设你的相机图像是 **1280×720（宽×高）**，第一帧先在原图上确定要跟踪的目标框，再**以目标框为中心裁出一块正方形区域，缩放到 128×128**。从第二帧开始，以**上一帧的跟踪框**为中心裁剪搜索区域，缩放到 **256×256**。这是 LiteTrack-B6 官方配置使用的两种输入尺寸。

**1. 第一帧怎样得到模板图 [1, 3, 128, 128]？**

假设在第一帧检测到一个行人，目标框已经映射回 **1280×720 原图坐标系**：

```plain
目标框 [x, y, w, h] = [560, 240, 80, 180]
左上角 = (560, 240)
中心点 = (600, 330)
```

模板裁剪系数为 `2.0`。用目标框的宽、高计算正方形裁剪区域的边长：

$$L_z=\left\lceil 2\sqrt{w h}\right\rceil =\left\lceil 2\sqrt{80\times180}\right\rceil =240\ \text{像素}$$

所以在原图上，以 `(600, 330)` 为中心，向左右、上下各取 `120` 像素。用 NumPy / OpenCV 表示就是：

```plain
# frame.shape == (720, 1280, 3)，数组索引顺序是 [y, x]
template = frame[210:450, 480:720]               # 240×240，包含行人和周围背景
template = cv2.resize(template, (128, 128))      # 128×128
```

这个例子中的裁剪区域完全在原图内。如果目标靠近画面边缘，裁剪区域越界时要先补边，保证裁出的区域仍是正方形。

**2. 图像怎样归一化？**

如果 `frame` 来自 OpenCV，通常是 **BGR**，先转成 **RGB**。然后把像素除以 `255`，再按 RGB 三个通道分别减均值、除以标准差：

```plain
template_rgb = cv2.cvtColor(template, cv2.COLOR_BGR2RGB)
z = torch.from_numpy(template_rgb).permute(2, 0, 1).float() / 255.0
mean = torch.tensor([0.485, 0.456, 0.406]).view(3, 1, 1)
std  = torch.tensor([0.229, 0.224, 0.225]).view(3, 1, 1)
z = ((z - mean) / std).unsqueeze(0)              # [1, 3, 128, 128]
```

此时 `z` 就是你上一条里送入 **Patch Embed** 的模板图。若相机接口已经输出 RGB，可以直接从 `torch.from_numpy` 开始。	

**3. 同一个初始框怎样送给 target_token_embed？**

这里要区分**图像像素归一化**和**目标框坐标归一化**。目标框需要跟着模板一起裁剪、缩放，最后表示成**相对于模板**的 `[x1, y1, x2, y2]`。以上面的例子看：

| 坐标所在位置 | 目标框 `[x1, y1, x2, y2]` |
| --- | --- |
| 1280×720 原图 | `[560, 240, 640, 420]` |
| 240×240 裁剪图，减去裁剪左上角 `(480, 210)` | `[80, 30, 160, 210]` |
| 相对于裁剪图的归一化坐标，按连续边界近似 | `[0.333, 0.125, 0.667, 0.875]` |


如果你直接调用官方跟踪器，**只需传入 RGB 原图和原图上的 [x, y, w, h]**。initialize() 内部会完成模板裁剪、像素归一化和目标框坐标变换，无需手动重复处理。

```plain
tracker.initialize(frame_rgb, {"init_bbox": [560, 240, 80, 180]})
```

**第二帧**假设上一帧框仍为 `80×180`，搜索系数改为 `4.0`，裁剪边长就是 $4\sqrt{80\times180}=480$ 像素。于是从新的 1280×720 图像中裁出 **480×480**，缩放到 **256×256**，按同样方式归一化后得到搜索张量 **[1, 3, 256, 256]**，与首帧缓存的模板特征进行匹配。

#### 3.1.2 裁剪会导致的问题
在 LiteTrack 里，裁剪最主要的问题是**视野变小**。对首帧模板和后续搜索图，它造成的影响不同：

| 场景 | 裁剪会带来什么问题 | 对跟踪的影响 |
| --- | --- | --- |
| **首帧模板裁掉部分目标** | 初始框偏移，或行人太细长，头部、脚部可能落在模板外 | 缓存的模板缺少这部分外观信息，后续匹配时可用的线索变少 |
| **后续帧目标移出搜索窗口** | 搜索窗口以上一帧预测位置为中心。行人突然加速，或四足机器人快速转身，目标可能部分或完全移出窗口 | 部分移出时，预测框可能不准；完全移出时，当前搜索图中没有目标可供匹配 |
| **上一帧定位误差累积** | 如果上一帧预测框偏右，下一帧的搜索窗口也会跟着偏右 | 连续几帧偏移后，可能跟丢目标，或误跟旁边外观相似的人 |


拿前面的 **80×180 行人框**举例：搜索窗口是 **480×480**。假设上一帧定位准确、行人大小不变，竖直方向每侧的余量是 **(480−180)/2 = 150 像素**。如果机器人突然低头，使行人在图像中向上移动 **180 像素**，那么即使行人仍完整出现在 **1280×720 原图**里，他的顶部也已经有 **30 像素**落在搜索窗口外。

**窗口大小需要权衡**：裁得小，目标缩放后占的像素多，细节更清楚，但容易出窗；裁得大，能容纳更大的帧间位移，但缩放到固定的 `256×256` 后，目标会变小。

### 3.2 Patch Embed
定义在 vit_cae_async.py#L242-L268。模板和搜索共用同一个卷积。

```python
        self.proj = nn.Conv2d(in_chans, embed_dim,
                              kernel_size=patch_size, stride=patch_size)
    # …

    def forward(self, x, mask=None):
        x = self.proj(x)
        if self.flatten:
            x = x.flatten(2).transpose(1, 2)  # BCHW -> BNC
        return x
```

卷积核和步长都是 16，每个输出位置只看一个 16 × 16 × 3 的图像块，等价于对每个图像块做一次 `768 × 768` 的线性投影。

|  | 模板 | 搜索 |
| --- | --- | --- |
| 输入 | `[B, 3, 128, 128]` | `[B, 3, 256, 256]` |
| 卷积输出 | `[B, 768, 8, 8]` | `[B, 768, 16, 16]` |
| `flatten(2).transpose(1, 2)` 之后 | `[B, 64, 768]` | `[B, 256, 768]` |
| 一个 token 对应的图像区域 | 裁剪图上 16 × 16 像素 | 裁剪图上 16 × 16 像素 |


参数量是 `768 × 3 × 16 × 16 + 768 = 590,592`。`flatten(2)` 按行展开，所以 token 的顺序就是空间上从左到右、从上到下的顺序，3.9 节重排特征图时依赖这一点。

**768 是 ViT-Base 主干设定的特征维度**，也就是规定“每个 patch 用 768 个数字表示”。

在 LiteTrack 的 Patch Embed 中，通过卷积的 **768 个输出通道**实现：

```plain
nn.Conv2d(
    in_channels=3,      # RGB 图像
    out_channels=768,   # 每个 patch 输出 768 个特征
    kernel_size=16,
    stride=16
)
```

对模板图来说：

```plain
[1, 3, 128, 128]
       ↓ 卷积
[1, 768, 8, 8]
       ↓ 整理排列
[1, 64, 768]
```

可以这样理解：

- 图像被划分为 **64 个 patch**。
- **768 个卷积核**分别对每个 patch 进行计算。
- 每个卷积核产生一个数，因此每个 patch 得到 **768 个数**。

**位置编码也采用 768 维，是为了能与 patch 特征逐元素相加。**

这里恰好有 `16×16×3=768`，但输出维度由代码中的 `out_channels=768` 决定。若将它设为 `384`，每个 patch 就输出 384 个特征，后续网络的维度也需要相应匹配。

### 3.3 位置编码
Patch Embed 本身不带位置信息。`finetune_track`（vit_cae_async.py#L405-L451）从骨干原来的位置编码插值出两份新的：

```python
        patch_pos_embed = self.pos_embed[:, patch_start_index:, :]   # [1, 197, 768] → [1, 196, 768]，跳过 CLS
        patch_pos_embed = patch_pos_embed.transpose(1, 2)            # [1, 768, 196]
        # …
        patch_pos_embed = patch_pos_embed.view(B, E, P_H, P_W)       # [1, 768, 14, 14]

        # Pos embedding for search region
        H, W = search_size
        new_P_H_S, new_P_W_S = H // new_patch_size, W // new_patch_size
        search_patch_pos_embed = nn.functional.interpolate(patch_pos_embed, size=(new_P_H_S, new_P_W_S), mode='bicubic',
                                                           align_corners=False)      # [1, 768, 16, 16]
        search_patch_pos_embed = search_patch_pos_embed.flatten(
            2).transpose(1, 2)                                          # [1, 256, 768]

        # Pos embedding for template region
        # … 同样插值到 8 × 8，得到 [1, 64, 768]

        self.pos_embed_z = nn.Parameter(template_patch_pos_embed)
        self.pos_embed_x = nn.Parameter(search_patch_pos_embed)
```

CAE 预训练用的是 224 × 224 的输入，对应 14 × 14 个 patch。这里用双三次插值把它变成 8 × 8 和 16 × 16 两份，保存为两个可训练参数，第一维是 1，加到 `[B, N, 768]` 上时按 batch 广播。

**1．CAE 原来准备了 196 张位置标签。**

`224×224` 的图像，每隔 `16×16` 切一块，就有 **14 行、14 列，共 196 块**。每块配一张标签，所以位置编码的形状是：

```plain
[1, 196, 768]
     ↑    ↑
  196张标签  每张标签有768个数字
```

**2．LiteTrack 需要的标签数量变了。**

| 图像 | 切成多少块 | 需要多少张位置标签 |
| --- | --- | --- |
| CAE 原来的图像 `224×224` | 14×14 | 196 张 |
| LiteTrack 模板图 `128×128` | 8×8 | 64 张 |
| LiteTrack 搜索图 `256×256` | 16×16 | 256 张 |


所以，要把原来的 **14×14 标签网格**，分别调整成 **8×8** 和 **16×16**。

这一步就像你熟悉的图片缩放。图片缩放通常处理 RGB 的 **3 个通道**，这里处理的是位置标签的 **768 个通道**。**双三次插值就是完成这种网格缩放的计算方法**。

**3．得到两套标签后，训练还可以修改它们。**

插值生成的数字作为初始值。模型训练时，继续调整这些数字，这就是“保存为两个可训练参数”。

**4．“第一维为 1，按 batch 广播”只是说，同一套标签可以给多张图使用。**

假设一次处理 4 张模板图，每张都有 64 个图块：

```plain
第1张图的64个图块 + 同一套64张位置标签
第2张图的64个图块 + 同一套64张位置标签
第3张图的64个图块 + 同一套64张位置标签
第4张图的64个图块 + 同一套64张位置标签
```

因此，**一次输入多少张图，都共用这一套模板位置编码**。搜索图则共用另一套搜索位置编码。

| 参数 | 形状 | 参数量 | 加在哪 |
| --- | --- | ---: | --- |
| `pos_embed_z` | `[1, 64, 768]` | 49,152 | 模板 token |
| `pos_embed_x` | `[1, 256, 768]` | 196,608 | 搜索 token |


骨干原来的 `pos_embed [1, 197, 768]` 在插值之后不再参与前向，但仍然留在模型里。它在不加载 CAE 权重时的取值见第 7 节第 5 条。

**pos_embed_z 和 pos_embed_x 是两组独立的可学习参数。** 更准确地说，它们是两张“位置向量表”。

| 位置编码 | 对应输入 | 参数形状 | 参数量 |
| --- | --- | --- | --- |
| `pos_embed_z` | 模板图的 64 个 patch | `[1, 64, 768]` | 49,152 |
| `pos_embed_x` | 搜索图的 256 个 patch | `[1, 256, 768]` | 196,608 |


**初始化时**，两者由同一份预训练位置编码，分别插值到 **8×8** 和 **16×16** 的网格得到。

**训练时**，两组参数分别接收梯度、分别更新。例如，模板左上角的位置向量和搜索图左上角的位置向量，可以逐渐学成不同的数值。它们的更新都由最终跟踪损失通过反向传播驱动。

**推理时**，使用训练好的固定数值，逐帧处理图像时无需更新这些参数。

#### 3.3.1 14×14 怎么变成 8×8
通过“双三次插值”，把 14×14 的位置编码网格缩小到 8×8。 你可以把它想成一张 14×14 像素、具有 768 个通道的小图片。

先只看其中 **1 个通道**，它就是一张存有数字的 `14×14` 表格。缩小后，需要计算出一张新的 `8×8` 表格。

**新表格中的每个数字怎么得到？**

1. 确定新位置对应到原来 `14×14` 网格的哪里。
2. 找到它周围的 **4×4，共 16 个旧数值**。
3. 根据距离计算权重，将这 16 个数加权组合，得到一个新数值。
4. 对新网格的全部 **64 个位置**重复计算，就得到 `8×8`。

**768 个通道各自完成同样的操作**，所以通道数保持 768：

```plain
原位置编码       [1, 768, 14, 14]
                         ↓ 双三次插值
新位置编码       [1, 768,  8,  8]
                         ↓ 展平空间维度并调整排列
模板位置编码     [1, 64, 768]
```

代码里直接指定目标尺寸即可：

```plain
pos_8x8 = F.interpolate(
    pos_14x14,             # [1, 768, 14, 14]
    size=(8, 8),           # 指定输出网格大小
    mode="bicubic",         # 双三次插值
    align_corners=False,
)
```

生成的 64 个位置向量都经过重新计算，因此能把原来 196 个位置上的信息调整到新的网格中。

### 3.4 目标框 token
B6 的 `USE_CLS_TOKEN=True`。它和 ViT 的分类 token 不是一回事：这是一个由模板框坐标算出来的 token，告诉模板编码“目标在模板图的什么位置”。定义在 litetrack.py#L63-L65：

```python
        if self.add_target_token:
            self.target_token_embed = Mlp(
                4, out_features=self.backbone.embed_dim)
```

`Mlp` 的 `hidden_features` 默认等于 `in_features`（litetrack.py#L22），所以这里隐藏层只有 4 维：`Linear(4 → 4) → GELU → Linear(4 → 768)`，共 3,860 个参数。

```python
            target_token = self.target_token_embed(template_bb).unsqueeze(-2)
```

| 步骤 | 维度 |
| --- | --- |
| `template_bb`，模板裁剪图下的归一化 `xyxy` | `[B, 4]` |
| `target_token_embed(...)` | `[B, 768]` |
| `.unsqueeze(-2)` | `[B, 1, 768]` |


这个 token 在加完位置编码之后才拼到模板序列开头，所以没有位置编码。

**训练和推理对它的用法不一样，这是读这份代码最容易漏掉的地方。** 推理时，`forward_z` 把它拼到 64 个模板 token 前面，65 个 token 一起过 6 个 Block，最后再去掉。训练时它不进入任何 Block，原因见 3.8 节。实测：固定模板图和搜索图，只更换 `template_bb`，训练路径的四个输出最大差异都是 0，反传后 `target_token_embed` 四个参数的梯度也都是 0。

#### 3.4.1 实例
目标框 token（target token）是把初始目标框的 4 个坐标，转换成一个 768 维向量，用来告诉网络“模板图里，要跟踪的目标位于哪里”。

模板图里同时包含目标和背景。例如模板中既有行人，也有路边车辆，目标框 token 就为网络提供行人所在区域的信息。

假设目标在模板图中的归一化坐标是：

```plain
[x1, y1, x2, y2] = [0.33, 0.125, 0.67, 0.875]
```

LiteTrack 将这 4 个数送进一个 MLP：

```plain
目标框坐标          [1, 4]
                       ↓ Linear(4, 4)
                    [1, 4]
                       ↓ GELU 激活
                    [1, 4]
                       ↓ Linear(4, 768)
                    [1, 768]
                       ↓ 增加 token 数量这一维
目标框 token        [1, 1, 768]
```

**得到的 768 个数，是网络根据框坐标计算出的特征。** MLP 中的权重通过训练学习。

然后，把它拼在模板的 64 个图像 token 前面：

```plain
目标框 token             模板图像 token
[1, 1, 768]              [1, 64, 768]
             ↓ 拼接
          [1, 65, 768]
             ↓
     进入模板特征提取层
```

这时，65 个 token 中，**1 个提供目标框的位置提示，64 个提供图像内容**。注意力计算让图像特征能够结合这个位置提示。

它和前面的位置编码作用不同：

| 信息 | 表达什么 |
| --- | --- |
| 图像位置编码 | 每个 patch 在模板网格中的位置 |
| 目标框 token | 整个模板中，初始目标框的位置和大小 |


### 3.5 Block 内部：注意力、MLP、LayerScale
每个 Block 由 `norm1`、`attn`、`norm2`、`mlp` 和两个 LayerScale 系数组成（vit_cae_async.py#L188-L210）。B6 走 `init_values=0.1` 的分支，所以有 `gamma_1`、`gamma_2`。

注意力模块叫 `MixedCrossAttention`（vit_cae_async.py#L161-L185）。`len_t` 决定哪些 token 发起查询：

```python
    def forward(self, x, len_t):
        B, N, C = x.shape
        qkv_bias = None
        if self.q_bias is not None:
            qkv_bias = torch.cat((self.q_bias, torch.zeros_like(
                self.v_bias, requires_grad=False), self.v_bias))
        qkv = F.linear(input=x, weight=self.qkv.weight, bias=qkv_bias)          # [B, N, 2304]
        qkv = qkv.reshape(B, N, 3, self.num_heads, -1).permute(2, 0, 3, 1, 4)    # [3, B, 12, N, 64]
        q, k, v = qkv[0], qkv[1], qkv[2]                                         # 各 [B, 12, N, 64]
        q_s = q[:, :, len_t:]                                                    # [B, 12, N-len_t, 64]

        attn = (q_s @ k.transpose(-2, -1)) * self.scale                          # [B, 12, N-len_t, N]
        # …
        attn_s2ts = attn
        attn_s2ts = attn_s2ts.softmax(dim=-1)                                    # [B, 12, N-len_t, N]

        x_t = x[:, :len_t]                                                       # [B, len_t, 768]
        x_s = (attn_s2ts @ v).transpose(1, 2).reshape(B, N-len_t, C)             # [B, N-len_t, 768]
        x = torch.cat((x_t, x_s), dim=1)                                         # [B, N, 768]
        x = self.proj(x)                                                         # [B, N, 768]
        x = self.proj_drop(x)
        return x
```

几个细节：

- Q、K、V 由一个 `[2304, 768]` 的权重一次算出，再切成 12 个头。偏置是 `[q_bias, 0, v_bias]`，也就是 K 没有偏置。`self.scale` 是 `64⁻⁰·⁵ = 0.125`。
- 只有前 `len_t` 个 token 之后的部分产生查询，但所有 `N` 个 token 都提供 K 和 V。注意力矩阵是 `[N − len_t, N]`，softmax 在最后一维做，所以一个搜索 token 对模板位置和搜索位置的权重加起来等于 1。
- 前 `len_t` 个 token 的输入 `x_t` 不加任何修改就拼回输出。
- 代码里 `attn_drop` 写在 softmax 之前，但 B6 的 `attn_drop_rate` 是 0，这一步是恒等映射。

`Block.forward`（vit_cae_async.py#L222-L239）：

```python
    def forward(self, x, len_t):
        # Here we keep the template part unchanged
        x_t = x[:, :len_t]
        x_s = x[:, len_t:]

        y= self.attn(self.norm1(
            torch.cat((x_t, x_s), dim=1)), len_t)
        y_s = y[:, len_t:]

        if self.gamma_1 is None:
            x = x + self.drop_path(y)
            x = x + self.drop_path(self.mlp(self.norm2(x)))
        else:
            x_s = x_s + self.drop_path(self.gamma_1 * y_s)
            x_s = x_s + self.drop_path(self.gamma_2 *
                                       self.mlp(self.norm2(x_s)))
            x = torch.cat((x_t, x_s), dim=1)
        return x
```

B6 构造时传了 `init_values=0.1`，`gamma_1` 不是 `None`，所以走 `else` 分支：注意力输出先乘 `gamma_1`，MLP 输出先乘 `gamma_2`，再各自加回残差。MLP 是 `Linear(768 → 3072) → GELU → Linear(3072 → 768)`。残差更新和 MLP 只作用于查询部分 `x_s`，`x_t` 原样拼回。

同一个 Block 有三种调用场景，下表是实测的内部维度（`B = 1`）。

| 步骤 | 模板编码，Block 0 到 5 | 搜索自注意力，Block 0 到 2 | 搜索读模板，Block 3 到 5 |
| --- | --- | --- | --- |
| 输入 `x` | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 320, 768]`，前 64 是模板 |
| `len_t` | 0 | 0 | 64 |
| `norm1(x)` | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 320, 768]` |
| `qkv` | `[1, 65, 2304]` | `[1, 256, 2304]` | `[1, 320, 2304]` |
| `q`、`k`、`v` | 各 `[1, 12, 65, 64]` | 各 `[1, 12, 256, 64]` | 各 `[1, 12, 320, 64]` |
| `q_s` | `[1, 12, 65, 64]` | `[1, 12, 256, 64]` | `[1, 12, 256, 64]` |
| `attn`，softmax 前后 | `[1, 12, 65, 65]` | `[1, 12, 256, 256]` | `[1, 12, 256, 320]` |
| `attn @ v`，合并头之后 | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 256, 768]` |
| 拼回 `x_t`，过 `proj` | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 320, 768]` |
| `y[:, len_t:]` | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 256, 768]` |
| `mlp(norm2(x_s))` | `[1, 65, 3072]` 到 `[1, 65, 768]` | `[1, 256, 3072]` 到 `[1, 256, 768]` | `[1, 256, 3072]` 到 `[1, 256, 768]` |
| 输出 | `[1, 65, 768]` | `[1, 256, 768]` | `[1, 320, 768]` |


训练时每个 Block 的 drop-path 率按层线性递增，实测是 `[0, 0.02, 0.04, 0.06, 0.08, 0.1]`。推理时不起作用。

### 3.6 模板编码：`forward_z`
vit_cae_async.py#L506-L524：

```python
        z = self.patch_embed(z)                    # [B, 3, 128, 128] → [B, 64, 768]
        z += self.pos_embed_z                      # [B, 64, 768]
        z = self.pos_drop(z)

        if self.add_target_token and target_token is not None:
            z = torch.cat([target_token, z], dim=1)  # [B, 65, 768]

        for i, blk in enumerate(self.blocks):
            z = blk(z, 0)                          # 6 个 Block，都是自注意力

        if self.add_target_token and target_token is not None:
            z = z[:,1:]                            # [B, 64, 768]
        return z
```

模板编码全程只有自注意力，看不到搜索图。65 个 token 里的目标框 token 通过自注意力影响其余 64 个模板 token 的特征。输出的 `[B, 64, 768]` 就是缓存的模板特征。**编码过程中有 65 个 token，最终缓存的是 64 个图像 token 的特征**。目标框 token 已经通过注意力计算影响了图像特征，输出前执行 `z = z[:, 1:]`，将它移除。

骨干末尾的 `self.norm` 是 `nn.Identity()`（vit_cae_async.py#L393-L394），所以 `forward_zx` 结尾那句 `x = self.norm(x)` 不改变任何数值。

### 3.7 搜索编码：`forward_zx`
vit_cae_async.py#L483-L504：

```python
        x = self.patch_embed(x)                    # [B, 3, 256, 256] → [B, 256, 768]
        x += self.pos_embed_x                      # [B, 256, 768]
        x = self.pos_drop(x)

        len_z = self.pos_embed_z.shape[1]          # 64

        if self.add_target_token and target_token is not None:
            z = torch.cat([target_token, z], dim=1)

        for i in range(self.num_FE_layers):        # B6：Block 0, 1, 2
            x = self.blocks[i](x, 0)               # [B, 256, 768]

        if self.add_target_token and target_token is not None:
            z = z[:,1:]

        x = torch.cat((z, x),dim=1)                # [B, 320, 768] = 模板 64 + 搜索 256
        for i in range(self.num_FE_layers, self.depth):   # B6：Block 3, 4, 5
            x = self.blocks[i](x, len_z)           # [B, 320, 768]

        x = self.norm(x)
        return x
```

分两段：

- **前 3 层**只处理 256 个搜索 token，`len_t=0`，是纯粹的搜索自注意力。
- **后 3 层**处理拼接后的 320 个 token，`len_t=64`。256 个搜索 token 发起查询，在 64 个模板 token 和 256 个搜索 token 上做 softmax；64 个模板 token 只提供 K、V，自己的输出被丢弃，Block 输出的前 64 个位置还是输入的 `z`。

实测 `forward_zx` 输出 `[1, 320, 768]`，其中前 64 个 token 与输入的 `z_feat` 最大差异为 0。模板特征不会被搜索图修改。由于 `z_feat` 每帧相同，后 3 层里模板 token 的 LayerNorm、QKV 投影和 `proj` 结果每帧也都相同，而当前实现每帧都重新算一遍。

`num_FE_layers` 在构造时算好（vit_cae_async.py#L386）：`depth − num_async_interaction_stage`，B6 是 `6 − 3 = 3`。

### 3.8 三个前向入口
骨干的 `forward`（vit_cae_async.py#L526-L539）按 `mode` 分派，上层包装模型对应三个入口。

| 包装模型的入口 | 传给骨干的 `mode` | 实际路径 | 模板编码的 token 数 | 谁在调用 |
| --- | --- | --- | ---: | --- |
| `forward_z` | `'z'` | `forward_z(z, target_token)` | 65 | 推理的 `initialize` |
| `forward` | `'x'` | `forward_zx(z_feat, x)` | 不编码模板 | 推理的每一帧 |
| `forward_train` | `None` | `forward_z(z)`，再 `forward_zx(z_feat, x, target_token)` | 64 | 训练 |


训练入口和另外两个入口不同的地方在 `mode=None` 的路径上：

```python
        if mode is None:
            z_feat = self.forward_z(z)                                    # 没有传 target_token
            x_feat = self.forward_zx(z_feat, x, target_token=target_token)
```

`forward_z(z)` 没有带目标框 token，模板以 64 个 token 过完 6 层。随后 `forward_zx` 把 token 拼到模板特征前面，但 3.7 节的代码里，前 3 个 Block 只处理搜索特征，进交互层之前 token 又被 `z = z[:,1:]` 切掉了。实测训练路径里模板 Block 的输入是 `[1, 64, 768]`，推理路径里是 `[1, 65, 768]`。

实测还确认了另一件事：`forward_train(z, x)` 的输出与“`forward_z(z)` 不带 token，再 `forward(z_feat, x)`”完全相同，最大差异为 0。也就是说训练时的前向就是推理的逐帧路径加上一次不带 token 的模板编码，和推理实际使用的模板编码差一个 token。

### 3.9 `forward_head`：从 token 序列到特征图
litetrack.py#L101-L124：

```python
            enc_opt = cat_feature[:, -self.feat_len_s:]                          # [B, 320, 768] → [B, 256, 768]
            opt = (enc_opt.unsqueeze(-1)).permute((0, 3, 2, 1)).contiguous()    # [B, 1, 768, 256]
            bs, Nq, C, HW = opt.size()                                          # B, 1, 768, 256
            opt_feat = opt.view(-1, C, self.feat_size_s, self.feat_size_s)      # [B, 768, 16, 16]

            score_map_ctr, bbox, size_map, offset_map = self.box_head(
                opt_feat, self.feat_size_s)
            # …
            outputs_coord_new = outputs_coord.view(bs, Nq, 4)                   # [B, 1, 4]
            out = {'pred_boxes': outputs_coord_new,
                   'score_map': score_map_ctr,                                  # [B, 1, 16, 16]
                   'size_map': size_map,                                        # [B, 2, 16, 16]
                   'offset_map': offset_map}                                    # [B, 2, 16, 16]
```

骨干输出 `[B, 320, 768]`，前 64 个是原样透传的模板 token，预测头只用最后 256 个搜索 token。通道维从最后一维换到第二维，再按 3.2 节的展开顺序排回 16 × 16 的特征图。`unsqueeze(-1)` 引入的 `Nq` 恒为 1。

#### 3.9.1 实例
**forward_head 先取出搜索图对应的 token，把它们还原成二维特征图，再交给预测头输出目标框。**

以 LiteTrack-B6 的 **128×128 模板、256×256 搜索图**为例，主干输出是：

```plain
cat_feature：[B, 320, 768]
                ↑
         64个模板token + 256个搜索token
```

**第一步，取出最后 256 个搜索 token。**

```plain
enc_opt = cat_feature[:, -256:]# [B, 256, 768]
```

这些搜索 token 已经在前面的交互层中融合了模板信息，预测头用它们来判断目标的位置。

**第二步，把序列重新排列成 16×16 的空间网格。**

搜索图经过 Patch Embed 时，原本就是一个 **16×16 的网格**，随后才展平成 256 个 token。现在按照相同顺序放回去：

| 序列位置，从 0 开始 | 特征图中的位置 |
| --- | --- |
| token 0 | 第 1 行、第 1 列 |
| token 1 | 第 1 行、第 2 列 |
| token 15 | 第 1 行、第 16 列 |
| token 16 | 第 2 行、第 1 列 |
| token 255 | 第 16 行、第 16 列 |


维度变化可以简化理解为：

```plain
# 将通道维度移到前面
feature = enc_opt.transpose(1, 2)
# [B, 768, 256]

# 将256个空间位置恢复为16×16
feature = feature.reshape(B, 768, 16, 16)
# [B, 768, 16, 16]
```

**每个网格位置都保留一个 768 维特征向量。** 这一步只改变数据排列，768 个通道和 256 个位置的特征数值都得到保留。

### 3.10 预测头：`CenterPredictor`
head.py#L136-L240。输入 `[B, 768, 16, 16]`，三条互相独立的卷积分支并行运行。每条分支是四个 `3×3 Conv → BN → ReLU` 加一个 `1×1 Conv`，由辅助函数 `conv` 构造（head.py#L41-L54）：

```python
        return nn.Sequential(
            nn.Conv2d(in_planes, out_planes, kernel_size=kernel_size, stride=stride,
                      padding=padding, dilation=dilation, bias=True),
            nn.BatchNorm2d(out_planes),
            nn.ReLU(inplace=True))
```

三条分支的前四层结构相同，下表里的 `*` 代表 `ctr`、`offset`、`size` 中的任意一个：

| 层 | 通道变化 | 输出维度 |
| --- | --- | --- |
| 输入 |  | `[B, 768, 16, 16]` |
| `conv1_*`，3 × 3 卷积 + BN + ReLU | 768 → 256 | `[B, 256, 16, 16]` |
| `conv2_*`，3 × 3 卷积 + BN + ReLU | 256 → 128 | `[B, 128, 16, 16]` |
| `conv3_*`，3 × 3 卷积 + BN + ReLU | 128 → 64 | `[B, 64, 16, 16]` |
| `conv4_*`，3 × 3 卷积 + BN + ReLU | 64 → 32 | `[B, 32, 16, 16]` |
| `conv5_ctr`，1 × 1 卷积 | 32 → 1 | `[B, 1, 16, 16]` |
| `conv5_offset`，1 × 1 卷积 | 32 → 2 | `[B, 2, 16, 16]` |
| `conv5_size`，1 × 1 卷积 | 32 → 2 | `[B, 2, 16, 16]` |


空间分辨率始终是 16 × 16，没有下采样。分支末端的处理不同：中心分支和尺寸分支过 sigmoid，再截到 `[1e-4, 1 − 1e-4]`；偏移分支直接用卷积输出，没有激活函数。

三个输出的含义：

| 输出 | 形状 | 每个格点的含义 | 取值 |
| --- | --- | --- | --- |
| `score_map` | `[B, 1, 16, 16]` | 目标中心落在这个格点的分数 | 0 到 1 |
| `size_map` | `[B, 2, 16, 16]` | 假设中心在此格点时，目标的宽、高（相对搜索图的归一化值） | 0 到 1 |
| `offset_map` | `[B, 2, 16, 16]` | 中心相对格点左上角的偏移，单位是格长 | 不限 |


四个 3 × 3 卷积叠起来，每个输出格点能看到输入特征图上 9 × 9 个格点的范围。实测用梯度验证：`score_map[8, 8]` 对输入的非零梯度落在第 4 到 12 行、第 4 到 12 列。换算到搜索图上是 144 × 144 像素。

BN 是普通的 `nn.BatchNorm2d`，因为 `build_box_head` 没有传 `freeze_bn`，默认是 `False`。训练时用 batch 统计量，推理时用滑动平均。

#### 3.10.1 实例
（与 3.11 节的解码过程对照。）

假设搜索图是 **256×256**，里面有一个行人。网络已经得到 **[1,768,16,16]** 的特征图，接下来由三个分支预测他的目标框。

**① 中心得分分支，寻找行人中心。**

它给 16×16 个位置分别打分，假设其中三个位置是：

| 位置 `(x,y)`，从 0 开始 | 中心得分 |
| --- | --- |
| `(6,9)` | 0.60 |
| **(7,9)** | **0.95，最高分** |
| `(8,9)` | 0.72 |


所以选中 **(7,9)**。接着去另外两个分支的**同一个位置**读取结果。

**② 宽高分支，读取行人的大小。**

假设位置 `(7,9)` 输出：

```plain
w = 0.25
h = 0.50
```

这是相对于搜索图的比例，因此：

```plain
行人框宽度 = 0.25 × 256 = 64 像素
行人框高度 = 0.50 × 256 = 128 像素
```

**③ 偏移分支，细化中心位置。**

假设位置 `(7,9)` 输出：

```plain
dx = 0.25
dy = 0.50
```

搜索图的 256 像素对应特征图的 16 格，所以**每格对应 16 像素**。修正后的中心为：

$$
\begin{aligned}
c_x&=(7+0.25)\times16=116\ \text{像素}\\
c_y&=(9+0.50)\times16=152\ \text{像素}
\end{aligned}
$$

**④ 组合成最终目标框。**

现在知道：

```plain
中心点：(116, 152)
宽、高：(64, 128)
```

从中心点分别减去一半宽高，就得到左上角：

```plain
左上角 x = 116 − 64/2  = 84
左上角 y = 152 − 128/2 = 88
```

所以，在这张 **256×256 搜索图**上，行人的框是：

```plain
[x, y, w, h] = [84, 88, 64, 128]
```

`CenterPredictor` 实际返回的则是归一化的中心坐标格式：

```plain
[cx, cy, w, h] = [0.453125, 0.59375, 0.25, 0.50]
```

### 3.11 解码：`cal_bbox`
head.py#L181-L199：

```python
        max_score, idx = torch.max(score_map_ctr.flatten(1), dim=1, keepdim=True)   # [B, 256] → idx [B, 1]
        idx_y = idx // feat_size                                                     # 行
        idx_x = idx % feat_size                                                      # 列

        idx = idx.unsqueeze(1).expand(idx.shape[0], 2, 1)                            # [B, 2, 1]
        size = size_map.flatten(2).gather(dim=2, index=idx)                          # [B, 2, 1]
        offset = offset_map.flatten(2).gather(dim=2, index=idx).squeeze(-1)          # [B, 2]

        bbox = torch.cat([(idx_x.to(torch.float) + offset[:, :1]) / feat_size,
                          (idx_y.to(torch.float) + offset[:, 1:]) / feat_size,
                          size.squeeze(-1)], dim=1)                                 # [B, 4]
```

过程是：把分数图展平成 256 个数，取最大值的位置 `idx`，换算成行 `idx // 16` 和列 `idx % 16`，再从同一个格点读出宽、高和偏移。解码结果：

```plain
cx = (列 + dx) / 16
cy = (行 + dy) / 16
w  = size_map[0, 行, 列]
h  = size_map[1, 行, 列]
```

`dx`、`dy` 的单位是格长。目标中心恰好在一个格点的正中间时，偏移应该是 0.5。

实测一例：峰在 `idx = 137`，即第 8 行、第 9 列，偏移 `(0, 0)`，尺寸 `(0.28777, 0.215827)`，解码结果是 `cxcywh = (0.5625, 0.5, 0.28777, 0.215827)`。换算成 256 搜索图上的像素是中心 `(144, 128)`，宽高 `(73.67, 55.25)`。
