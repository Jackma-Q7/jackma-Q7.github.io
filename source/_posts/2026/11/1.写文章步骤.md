这篇文章记录我更新博客的日常流程。博客使用 Hexo 和 Butterfly 主题，项目放在 `C:\Users\qq7\Desktop\my-blog`，线上地址是 <https://Jackma-Q7.github.io/>。

日常更新只需要：**新建 Markdown 文件 → 写文章 → 本地预览 → 提交并推送**。

## 一、文章放在哪里

文章统一放在项目的 `source/_posts/` 目录，可以继续按年份和月份建文件夹：

```text
my-blog/
├── source/
│   ├── _posts/
│   │   ├── 2026/
│   │   │   └── 11/
│   │   │       ├── 1.写文章步骤.md
│   │   │       └── 2.STM32串口学习.md
│   │   └── 2027/
│   │       └── 01/
│   └── images/
│       └── posts/
│           └── uart-demo/
│               └── wiring.jpg
├── _config.yml
└── _config.butterfly.yml
```

Hexo 会读取 `_posts` 下各级文件夹中的文章。比如这篇文章的位置是：

```text
C:\Users\qq7\Desktop\my-blog\source\_posts\2026\11\1.写文章步骤.md
```

注意：

- 文件后缀使用 `.md`，不要保存成 `.md.txt`。可以在资源管理器中开启“查看 → 显示 → 文件扩展名”。
- 年月文件夹用于整理源文件，不会自动变成网站上的分类。
- 首页按文章的 `date` 倒序排列，文件名前面的 `1.`、`2.` 不决定显示顺序。
- 不要把文章放在项目根目录的 `2026/` 中；当前配置不会把那里当作文章目录。

## 二、新建一篇文章

直接在编辑器中打开 `source/_posts/2026/11/`，新建 `2.STM32串口学习.md`，复制下面的模板：

```markdown
---
title: STM32 串口学习笔记
date: 2026-11-17 20:00:00
permalink: 2026/11/17/stm32-uart-notes/
categories:
  - 嵌入式开发
tags:
  - STM32
  - 串口通信
description: 记录 STM32 串口的接线、初始化和收发调试过程。
cover: /images/banner.jpg
---

这次主要学习 STM32 串口通信，记录实验过程和遇到的问题。

## 实验环境

- 开发板：填写实际型号
- 开发工具：填写实际软件和版本

## 实现步骤

在这里写接线方法、配置过程和关键代码。

## 遇到的问题

记录现象、排查过程和解决方法。

## 学习总结

写下这次学到的内容，以及后续准备验证的问题。
```

将标题、日期、分类、标签和正文换成自己的内容。文件开头两个 `---` 之间的部分叫 Front Matter，用来设置文章信息；第二个 `---` 后面才是正文。

| 字段 | 用途 | 填写建议 |
| --- | --- | --- |
| `title` | 网页显示的文章标题 | 可以和文件名不同 |
| `date` | 文章发布时间、归档月份和首页排序 | 使用实际日期，如 `2026-11-17 20:00:00` |
| `permalink` | 指定这篇文章的网址路径 | 每篇使用不同路径，结尾保留 `/`，发布后尽量不改 |
| `categories` | 网站分类 | 上面的写法表示“嵌入式开发”分类 |
| `tags` | 文章标签 | 可填写多个，用来标记相关技术 |
| `description` | 文章简介 | 用一两句话概括内容 |
| `cover` | 文章卡片封面 | 使用网站图片路径，省略时使用主题默认封面 |

YAML 的冒号后面要有空格，缩进使用空格。标题包含冒号等特殊符号时，可以加引号，例如 `title: "STM32：串口学习笔记"`。

项目默认的网址规则是 `年/月/日/文章名称/`，但在当前配置下，嵌套文件夹也会进入自动生成的文章名称中。为了让按年月整理的文章拥有简洁、固定的网址，建议像上面一样填写 `permalink`。示例文章发布后的地址为：

```text
https://Jackma-Q7.github.io/2026/11/17/stm32-uart-notes/
```

明确设置 `permalink` 后，修改标题、文件名、年月文件夹或 `date` 都不会自动改变网址；它会始终使用指定路径。新建下一篇文章时，记得换一个路径，避免与其他文章重复。路径中的日期也需要自己填写，文件夹名称不会覆盖文章中填写的日期。

也可以在项目根目录运行下面的命令创建文章，再将生成的文件移动到需要的年月文件夹：

```powershell
npx hexo new post "STM32串口学习"
```

该命令默认生成 `source/_posts/STM32串口学习.md`。手动新建和命令创建二选一即可。

## 三、正文常用写法

正文使用 Markdown。文章标题已经由 `title` 显示，正文通常从二级标题 `##` 开始。

````markdown
## 二级标题

### 三级标题

普通段落之间空一行。

**加粗文字**，以及 `行内代码`。

- 无序列表第一项
- 无序列表第二项

1. 操作第一步
2. 操作第二步

[Hexo 官方文档](https://hexo.io/zh-cn/docs/)

> 这里可以放补充说明。

```c
#include <stdio.h>

int main(void) {
    printf("Hello, STM32!\n");
    return 0;
}
```
````

代码块开头可以填写语言名称，如 `c`、`cpp`、`python` 或 `powershell`，方便网页显示代码高亮。

## 四、插入图片和修改封面

建议按文章建立图片文件夹。例如，把接线照片放到：

```text
C:\Users\qq7\Desktop\my-blog\source\images\posts\uart-demo\wiring.jpg
```

正文中这样引用：

```markdown
![STM32 串口接线示意图](/images/posts/uart-demo/wiring.jpg)
```

要把这张图作为封面，将文章开头的 `cover` 改为：

```yaml
cover: /images/posts/uart-demo/wiring.jpg
```

图片链接从 `/images/` 开始，不包含 `source`，使用正斜杠 `/`。不要填写 `C:\Users\...` 这样的电脑路径，线上网站无法读取电脑里的文件。

图片文件名建议使用英文、数字和短横线。文件名、大小写和后缀要与实际图片一致，GitHub Pages 上的路径区分大小写。

## 五、本地预览

打开 PowerShell，进入博客项目目录：

```powershell
cd C:\Users\qq7\Desktop\my-blog
npm run server
```

浏览器打开 <http://localhost:4000/>。保存文章后，等待终端完成重新生成，再刷新网页，检查标题、日期、分类、代码和图片。按 `Ctrl + C` 停止预览服务。

首次在新电脑上运行，或尚未安装依赖时，先安装 Node.js LTS（22 或 24），重新打开终端，再在项目根目录执行一次：

```powershell
npm ci
```

依赖已安装后，日常写文章不需要重复执行 `npm ci`。

如果 `4000` 端口已经被其他程序占用，可以换一个端口：

```powershell
npx hexo server -p 4001
```

然后访问 <http://localhost:4001/>。

修改 `_config.yml` 或 `_config.butterfly.yml` 后，建议停止并重新启动预览服务。若页面仍显示旧内容，先停止服务，再执行：

```powershell
npm run clean
npm run server
```

## 六、发布到 GitHub Pages

这个项目已配置 GitHub Actions，推送到 GitHub 仓库的 `main` 分支后，会自动构建并发布网站。

首次启用时，在 GitHub 仓库中打开 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。仓库地址是：

<https://github.com/Jackma-Q7/Jackma-Q7.github.io>

文章预览无误后，在项目根目录执行：

```powershell
npm run build
git status
git add .
git diff --cached --stat
git commit -m "新增 STM32 串口学习笔记"
git push origin main
```

`npm run build` 用于确认网站可以正常生成；`git add .` 会暂存项目中所有未被忽略的改动，提交前可以通过状态和暂存摘要确认本次内容。提交说明换成这次实际更新的内容。

推送后进入仓库的 **Actions**，查看 **Deploy Hexo to GitHub Pages**。等构建和部署均成功后，再打开 <https://Jackma-Q7.github.io/> 检查文章。

本地保存和预览不会自动更新线上网站；需要完成提交、推送，并等待部署成功。本项目使用 Actions 发布，不需要执行 `hexo deploy`，也不需要手动上传 `public/` 或 `node_modules/`。

## 七、常见问题

### 文章没有出现在首页

先确认文件位于 `source/_posts/` 下，后缀为 `.md`，开头的文章信息格式正确。放在 `source/_drafts/` 中的草稿默认不会显示。

首页按 `date` 倒序排列，每页显示 10 篇，较早的文章可能在后面的分页中，也可以去“博文 → 归档”查找。当前项目启用了未来日期文章的显示，填写日期时仍建议使用实际发布时间。

### 分类和标签没有更新

在文章开头填写 `categories` 和 `tags` 并保存，重新生成网站后会自动更新，无需手动编辑分类页和标签页。

如果要给文章设置两级分类，可以这样写；下面表示“嵌入式开发 → STM32”的层级关系：

```yaml
categories:
  - 嵌入式开发
  - STM32
```

### 本地有图片，线上却不显示

检查图片是否放在 `source/images/` 中、引用路径是否正确，以及图片是否随文章一起提交并推送。尤其注意文件名大小写和 `.jpg`、`.png` 等后缀。

### 推送成功，但线上还是旧文章

进入仓库的 **Actions** 查看部署是否已经完成。如果任务失败，打开失败步骤的日志查看原因；如果部署成功，再按 `Ctrl + F5` 强制刷新网页。

### 终端提示找不到 npm

确认已安装 Node.js LTS，并在安装后重新打开终端。可以分别运行 `node -v` 和 `npm -v` 检查安装是否生效。

## 日常更新速查

1. 在 `source/_posts/年份/月份/` 新建 `.md` 文件。
2. 填写文章信息和 Markdown 正文，将图片放到 `source/images/`。
3. 运行 `npm run server`，打开本地网页检查效果。
4. 运行 `npm run build`，确认构建成功。
5. 提交并推送到 `main`，等待 GitHub Actions 部署完成。
